# DSH 0.2.1 alpha.1: scoped runtime evidence

The official [v0.2.1-alpha.1 release](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.1) resolves to immutable commit `5badb15009ae1756c3afe0ae0cef1faafc290ccc`. It introduces an experimental Claude Code Mods layer and removes runtime invariant plugin exports. Neither change is assumed compatible with every existing plugin.

On Windows 11 / Node 24.19.0 / pnpm 11.7.0, a new detached checkout at that commit passed `pnpm install --frozen-lockfile`, `pnpm run build:lib`, CLI help, and stock headless config composition in a fresh `DSH_HOME`. Package-install warnings about absent pre-build CLI bin links were non-fatal.

Two *other* fresh, isolated `DSH_HOME` directories used the public fixed commits `dsh-support-lifecycle-proof@df33364fee39fbb55b53b8c290df6b28d0f072c6` and `dsh-windows-readiness-proof@46cc6b8dbaa0f970ffa326615cb1e52683516929`, installed with `github:` specs into Web and headless profiles respectively. The existing [profile business probe](profile-business-smoke.mjs) then booted each full profile Loader and called both plugins through the real ToolRuntime. Each profile passed the same six positive/negative cases: support inspect, support closed report with hash read-back, missing retirement non-closure, Windows readiness inspect, 26-control verified report with hash read-back, and workspace traversal rejection. Web and headless produced the same support SHA-256 `44ad888bce2f282554b8f6afa5971f4c0b1ff9e51bbb6a1918a1122e9f0fb6d6` and Windows SHA-256 `98fd800ccf76f57cea01edbf4e5e21f537a4da368bec6a14f03bca6a44780390`; these also match the earlier RC2 fixed-fixture results. Headless registered 28 tools and Web registered four, as their stock tool sets differ.

Separately, the [runtime verifier](../../scripts/runtime-verify.mjs) passed fixed `github:` support-lifecycle install, compose and Web boot in its own temporary home. Its content-addressed report `8444bbd090ad76319d158488ae4eca127d59148a558f6d987992761a3d4ee85d` was independently read back and SHA-256 matched. The runtime matrix now scopes this required positive-control target to the new alpha baseline, while keeping the older five targets on their original two baselines. Stock controls remain scheduled on Ubuntu and Windows for every baseline; scoped target controls run on both platforms.

These observations do **not** establish model-driven calls, Claude Code Mods interoperability, all 40 Labs, other third-party plugins, or a new default DSH baseline. The full-profile six-case business probe above ran locally on Windows; the runtime matrix separately verifies stock boot plus fixed bundle install/compose/boot on clean Ubuntu and Windows runners.
